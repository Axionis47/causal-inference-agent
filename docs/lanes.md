# Executable analysis endpoints

The authoritative declarations live in each family's `lane/knowledge/endpoints.yaml`, `space.yaml` and `rungs.yaml`. The generated ladders include every context requirement, assumption, decision trajectory, execution capability and terminal failure:

- [Adjustment](ladders/adjustment.md): twelve executable endpoints plus diagnostic ID expressions.
- [Difference in differences](ladders/diff_in_diff.md): six structural endpoints with explicit pooled, horizon and cohort targets.
- [Discontinuity](ladders/discontinuity.md): six combinations of sharp/fuzzy/eligibility target and continuity/local-randomisation framework.

Every lane separates reasoning, engine adapters, execution and artifacts. The desk admits context; a lane settles its design obligations and returns a typed deficiency when essential context was omitted. Frozen specifications and design-qualified addresses prevent result records from conflating different populations or inference choices. A declared capability remains conditional on its causal assumptions.

Adjustment's existing estimator-selection episode can write arbitrary Python for diagnostics when several eligible methods remain. Its three-call budget uses a read-only projection of the admitted analysis rows containing treatment and the identified adjustment columns. Outcome values and unrelated columns are withheld. Isolated execution permits the supplied table, runtime files and current step folder; weaker sandbox backends refuse this mode. Every pick must cite a successful code result with nonempty, finite numerical facts. Scripts, diagnostic outputs and the selected method remain in the trace and episode history. This first increment selects an existing estimator; inference, falsification and sensitivity policies retain their existing selection behavior.

DiD’s `probe` and discontinuity’s `line` can optionally use the same diagnostic tool and numerical-evidence gate. They reuse existing evidence without coding when that suffices. DiD code sees full assignment/time metadata, with outcomes and safe covariates masked from the earliest adoption onward. Discontinuity code sees oriented score, exact eligibility, optional receipt/cluster and approved predetermined covariates, with outcomes absent and missing-outcome rows retained. Once coding is attempted, a successful numerical probe must be cited. Diagnostic notes can leave causal uncertainty unresolved; they cannot rewrite targets, clustering or the engine’s inference and window policies.

The finite supported expansion excludes continuous dose and multiple treatment adjustment, complex mediation, generic CATE learners, arbitrary ID-expression estimation, GCM tasks, treatment reversals, nonlinear or survey-weighted DiD, irregular-period LP comparisons, regression kink, multiple-cutoff RD and clustered local-randomisation inference. These are explicit unsupported configurations.
